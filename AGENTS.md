# ReqHQ v2 Engineering & Verification Standards

Project-specific operating rules and lessons learned from Phases 1–5 of `reqhq` v2 (`C:\Projects\Agentic-Specification-Refinement`, Windows 11, Python 3.15.0).

## 1. Runtime, Environment & Live Tool Gates
- **Explicit Interpreter:** Always run Python, `pip`, and `pytest` via `.venv/Scripts/python.exe` (Python 3.15.0)—never bare `python` or global `pytest`.
- **Live Alloy 6.2 Gate by Default:** On machines with Temurin Java 21 and the Alloy 6.2 JAR installed, always export `REQHQ_ALLOY_JAR_PATH="C:/tools/alloy/org.alloytools.alloy.dist.jar"` (and ensure Temurin `java` is on `PATH`) before running `pytest` so `@pytest.mark.alloy_live` executes with **0 skipped**. Keep offline unit tests fast and self-contained via `MockAlloyAnalyzer` for zero-dependency CI.
- **Alloy 6.2 CLI Output Format:** Real Alloy 6.2 `exec` prints its summary table to **`stderr`** (not `stdout`), reports passing `check` commands as `UNSAT`, failing `check` counterexamples as `00. check <name> ... SAT`, and non-vacuous `run __vacuity_witness_*` checks as `SAT`. Always verify parsers against live JAR output in addition to mocks.
- **Python 3.15 Wheel Safety:** Check `--dry-run --only-binary=:all:` before adding dependencies; avoid C/Rust source builds or POSIX-only packages.
- **CLI Entry-Point Naming:** Always invoke `reqhq` via `.venv/Scripts/python.exe -m reqhq.cli` (not `-m reqhq`, as `src/reqhq/__main__.py` is intentionally absent). Keep docs (`REPRODUCIBILITY.md`, `docs/final_report/README.md`) aligned via regression assertions.

## 2. Windows 11 & Cross-Platform Discipline
- **`.gitattributes` Before LF-Strict Tests:** Git for Windows (`core.autocrlf = true`) converts `\n` to `\r\n` on checkout. Any directory whose tests assert LF-only line endings (`b"\r\n" not in raw`, e.g., `docs/adr/**`, `docs/final_report/**/*.md`, `REPRODUCIBILITY.md`, `data/benchmarks/**/*.{json,md,py}`) MUST have a matching `text eol=lf` rule in `.gitattributes` from day one.
- **Windows Temp-Dir Handle Safety:** Always pass `ignore_cleanup_errors=True` to `tempfile.TemporaryDirectory(...)` whenever spawning subprocesses whose `cwd` is inside the temp directory (prevents transient `PermissionError: [WinError 32]` during Windows teardown).
- **No POSIX-Only Assumptions:** Avoid hard dependencies on POSIX-only primitives (`os.fork()`, `mutmut` without fallback). Put a `Protocol` (such as `MutationRunner`) in front of Windows-native implementations (`ASTMutantEngine`) and POSIX adapters (`MutmutRunner`).

## 3. 100% Coverage & Strict Hypothesis PBT Standards
- **Zero `# pragma: no cover` Shortcuts:** Maintain **100.00% line coverage** across all modules in `src/reqhq/` without papering over reachable logic. Inspect every missed branch to distinguish real bugs or dead code from missing tests.
- **Mandatory Internal Hypothesis PBT:** Every new module/phase must ship deterministic Hypothesis property-based tests (`@given`, `@settings(derandomize=True, max_examples=50)` or `RuleBasedStateMachine`) alongside example unit tests.
- **Strict Pytest Warnings Gate:** Always run `pytest tests/reqhq` with `-W error::hypothesis.errors.HypothesisWarning -W error::pytest.PytestUnknownMarkWarning`. Register every custom pytest marker (`alloy_live`, `live_system`) in `pyproject.toml` immediately upon introduction.
- **Hypothesis Strategy Hygiene:**
  - Always set `allow_nan=False, allow_infinity=False` on float strategies unless testing NaN/Inf explicitly.
  - Use `not keyword.iskeyword(s)` rather than partial keyword lists for generated Python identifiers.
  - Set `deadline=None` on PBTs that perform filesystem/NTFS temp-dir I/O or subprocess calls.
  - Pin boundary edge cases (`0`, `1`, empty inputs, exact endpoints, `-0.0` normalization) explicitly via `@example(...)` or wide strategy ranges.

## 4. Preservation, Namespace Separation & Research Hygiene
- **Legacy Isolation:** Never modify `src/specpipe/`, `data/frozen/`, or legacy `tests/test_*.py` (all 87 legacy tests must remain untouched and passing).
- **STRICT DEV-SPLIT-ONLY Dataset Rule:** Development, debugging, and system tests (`tests/reqhq/system/**`) MUST ONLY read `data/frozen/*/dev/` (e.g., `0000 - cctns.pdf.txt`, `0000 - gamma j.pdf.txt`) and `data/benchmarks/cross_domain/cases.json`. NEVER read, inspect, or tune against `data/frozen/*/test/`; enforce via runtime guard (`assert_dev_split_only()`).
- **Scientific Honesty & Mock Quarantine:** Offline `--mock` / `MockCodingAgent` runs are strictly for pipeline dry-runs and CI. Evaluation analysis and reporting MUST fail closed (`MockRunQuarantineError`) when `--strict-live` is set or when even a single record in a live run is mock/spoofed.
- **ADR Namespace Separation:** Keep repository governance Nygard ADRs (`docs/adr/0001`–`00XX`, LF-only, managed by `ADRManager`) strictly separated from generated target-system Routing/Assumption ADRs (`<export_dir>/ADRs/ADR-RXXX.md`, `ADR-AXXX.md`). Enforce `docs/adr/` write-refusal guards on all export/handoff/PBT/eval CLI commands.
- **Monotonic & Lifecycle-Aware Assertions on Append-Only Artifacts:** Never hardcode exact total counts (`len(adrs) == N`, `len(audit_log) == 2*N`) or forbid valid Nygard lifecycle transitions (`actions == ["created", "accepted"]`, `archived is False` on superseded historical ADRs). Use monotonic/prefix assertions (`>= N`, `numbers[:N] == 0001..000N`, `actions[:2] == ["created", "accepted"]`, `include_archived=True`) so future phases can cleanly supersede and archive clashing ADRs (`ADR-0001`) without breaking earlier test suites.

## 5. Multi-Agent Swarm, Independent QA & Check-In Discipline
- **Independent QA Separation & No-Test-Weakening:** Author cross-phase black-box system tests (`tests/reqhq/system/**`) strictly from public specs/CLI contracts, pin their SHA-256 digests in `SYSTEM_QA_DEFECTS.md`, and forbid rectifiers from weakening assertions or skipping failing cases—fix root-cause defects in `src/reqhq/` instead.
- **Independent Post-Swarm Deliverable Audit:** Never trust worker self-reports. Physically inspect every created/edited file for completeness, zero `TODO`/`NotImplementedError` stubs, LF endings, doc-to-code filename/symbol parity (ADRs vs. live modules), and re-run the full verification suite (legacy + `tests/reqhq` + coverage + live Alloy + live Ollama) from scratch after the final edit.
- **Stacked PR Check-In Discipline:** When splitting work into disjoint ADR + implementation PRs targeting an integration branch, either merge each PR sequentially before cutting the next (so per-PR local `pytest` passes standalone), or batch-open all disjoint PRs upfront and run the full verification gate once all PRs are merged into the integration branch. Never use `git add -A` or `git add .`—stage explicit file manifests and keep local `CHECKIN_PLAN_*.md` gitignored.

## 6. Live LLM Runtime, Provider & Security Lessons Learned (Phase 4b)
- **Test Against Live Models Before Declaring Victory:** Offline `httpx.MockTransport` tests validate contract wiring, but real local/cloud APIs expose protocol and behavioral bugs invisible to mocks (`DEF-P4B-003`..`DEF-P4B-006`). Always run live smoke flows on real dev/benchmark documents with live Ollama, live cloud escalation, and live Alloy 6.2 before release.
- **Ollama Reasoning Models (`qwen3:*`) & Constrained Decoding (`ADR-0023`):** Reasoning models in Ollama default to thinking mode and exhaust `num_predict` on internal `thinking` tokens, emitting empty `response=""` under JSON/GBNF decoding. Always send `"think": False` by default whenever `format` or `grammar` is set (while honoring explicit boolean `request.metadata["think"]`), and verify compatibility with both primary (`qwen3:4b`) and fallback (`phi4-mini`) models.
- **Gemini `v1beta` Structured Output & Model Lifecycle (`ADR-0023`):**
  - Use `generationConfig.responseJsonSchema` (NOT `responseSchema`), because Pydantic v2 `ConfigDict(extra="forbid")` emits `$defs`, `$ref`, and `additionalProperties: false`, which `responseSchema` rejects with HTTP 400.
  - Keep `default_model` on an active non-deprecated model (`gemini-3.1-flash-lite`, overridable via `REQHQ_GEMINI_MODEL`), filter Gemini 3.x `{"thought": true}` parts before JSON parsing, and retry transient HTTP 503 (`UNAVAILABLE`) once with bounded backoff.
- **Explicit-Escalation Cloud Short-Circuit (`ADR-0023`):** When a caller passes an explicit audited `EscalationReason` (`FINAL_AUDIT`, `CRITIC_DISAGREEMENT`, `ALLOY_REPAIR_EXHAUSTED`, etc.) and cloud escalation is permitted (`not strict_local` and cloud providers configured), short-circuit directly to cloud (`0` redundant local SLM calls, cutting `TIER_0` latency from ~22–36s to ~1.5s) and fall back to local SLM only if all cloud providers fail or rate-limit.
- **Universal Stage `ProviderError` Resilience & Bounded PDF Fallbacks:** Every elicitation/synthesis stage (`decomposer.py`, `critics.py`, `triage.py`, `alloy/emitter.py`, `pbt/emitter.py`) MUST catch `ProviderError` and degrade cleanly to deterministic heuristics (`cloud_verified=False`). Offline PDF fallback decomposition MUST reassemble wrapped lines, filter cover/TOC/footer noise, and bound fallback node counts (`<= 24` total) so generated locked PBT suites never blow up >60s.
- **Zero-Plaintext Encrypted Credentials & Opt-In Live Probing (`ADR-0019`, `ADR-0023`):** Never ask users to paste API keys in chat or commit plaintext secrets. Store credentials via `reqhq auth setup` / `reqhq auth rotate` (masked input, Windows DPAPI + Fernet envelope, `.vault.enc` gitignored), reject `.env.example` placeholders, and keep live HTTP auth probes strictly opt-in (`--verify-live` on `doctor`, `auth setup`, `auth status`) so offline CI and `--strict-local` remain zero-network.
- **Verify Live CLI Router Wiring End-to-End:** Ensure CLI router factories (`_build_router`) actually attach decrypted cloud providers (`GeminiFreeProvider`/`GroqFreeProvider`), persistent `QuotaLedger`, and `PromptCache`—not just `OllamaLocalProvider`—and cover that wiring with unit tests.

## 7. Live Evaluation Path Resolution, Quota Telemetry & Progress Lessons (Phase 5, `ADR-0022`)
- **Resolve All Paths at Subprocess, Harness & Lock Boundaries (`DEF-P5-002`, `DEF-P5-003`):**
  - Never pass CWD-relative `Path` arguments into `subprocess.run(..., cwd=workspace_dir)`, `PYTHONPATH`, `write_contract_lock()`, `ExperimentHarness.run_trial()`, or `EvalOrchestrator`. When a user runs a CLI command with a relative `--out eval_live_full`, passing relative test targets alongside a nested `cwd` causes `pytest` to resolve paths twice (`workspace_dir / eval_live_full/... -> file or directory not found`), silently collapsing `pbt_pass_rate` to `0.0` and wasting repair rounds.
  - Always `.resolve()` `out_dir`, `workspace_dir`, `bundle_dir`, `cwd`, `test_targets`, and `pythonpath_entries` immediately at every public entry point (defense in depth), and include a `monkeypatch.chdir(tmp_path)` relative-path regression test + Hypothesis PBT for every subprocess-spawning or lock-writing module.
- **Single-Source Cloud Quota Accounting & Zero Cross-Layer Ledger Contamination (`DEF-P5-004`):**
  - Only count responses with `resp.cloud_verified == True` as cloud quota usage (`cloud_requests`, `cloud_tokens`)—never mislabel local Ollama SLM calls as cloud requests.
  - Never add shared SQLite `QuotaLedger` deltas on top of already-attributed per-record cloud counts across `LiveLLMCodingAgent` -> `ExperimentHarness` -> `StageTelemetryCollector.finish_stage()` (`include_ledger_delta=False` in `run_layer4()`). Cross-layer `start_stage()` timers spanning `eval resume` and Layer 3 triple-count Layer 3's ledger delta onto Layers 1 & 2 and corrupt H2 cloud-reduction metrics.
- **Always Stream Live Per-Unit Progress on Multi-Minute CLI Runs:** Long-running commands (`reqhq eval run`, `reqhq eval resume`) must stream per-unit progress lines (`[L1 i/N]`, `[L2 i/N]`, `[L3 i/N]`, `[L4]`) to `stderr` via an optional `progress_callback` so stdout stays machine-parseable while operators always have real-time observability.

## 8. Large-Scale Live Eval, Smart Ingestion & Operational Best Practices (`ADR-0024`–`ADR-0027`)
- **Share One Encrypted Vault Across Eval Sessions:** Always export `REQHQ_VAULT_PATH=".reqhq_sessions/credentials.vault.enc"` whenever starting a new live evaluation or ablation run with a fresh `--sessions-dir` (e.g., `.reqhq_sessions_v5`). This isolates `prompt_cache.db` and `quota_ledger.db` per experiment without re-prompting for API keys.
- **Verify Exact CLI Options via `--help` Before Suggesting Commands:** Never guess Typer flags or subcommand signatures (e.g., `auth rotate GROQ_API_KEY`, `eval run --mode live --cross-domain-suite extended --coding-suite extended`, separate `eval ablate` for Proposal B3, and `eval analyze` -> `eval report` -> `eval package`). Always verify exact options against `.venv/Scripts/python.exe -m reqhq.cli <cmd> --help` first.
- **Plain-Text Reasoning-Model Suppression & Multi-Line Codegen Guard (`DEF-P5-005`, `ADR-0027`):**
  - `OllamaLocalProvider` only auto-sends `"think": False` when `format` or `grammar` is set. Every plain-text `LLMRequest` (`response_schema=None`, e.g., Layer 1 elicitation) MUST explicitly set `metadata={"think": False}` and escalate empty responses via `EscalationReason.SCHEMA_RETRY_EXHAUSTED` so `qwen3:*` does not exhaust `num_predict` on hidden thinking tokens.
  - Code-generation system prompts (`_CODEGEN_SYSTEM_PROMPT`) MUST explicitly require clean multi-line `\n`-separated Python to prevent single-line syntax collapse on complex state machines.
- **Live Cloud Failover Models, `TIER_0` Timeouts & Serialized GPU/CPU Execution (`ADR-0027`):**
  - Keep `GroqFreeProvider` on an active verified model (`openai/gpt-oss-20b`, overridable via `REQHQ_GROQ_MODEL`); on any cloud `HTTP 404 model_not_found`, query the provider's `/models` endpoint to confirm active free-tier model IDs before changing defaults.
  - Keep `OllamaLocalProvider` default `timeout=120.0` (`REQHQ_OLLAMA_TIMEOUT`) for `TIER_0` inference, and **never overlap** live `eval run`, `eval ablate`, and full `pytest` runs on the same laptop—concurrent Ollama + pytest CPU contention causes 2–3× slowdowns and transient Hypothesis deadline flakes.
- **Eliminate Redundant LLM Passes & Discarded Escalations in Multi-Arm Studies (`ADR-0027`):**
  - When multiple benchmark/ablation arms evaluate subsets of independent critics on the same input graph (`AblationRunner`), iterate **per document**, evaluate each needed specialist critic **once**, skip unused `_arbitrate_disagreement()` escalations whose outputs are discarded, and checkpoint all arms immediately per document.
- **Pre-LLM Smart Ingestion Hygiene (`ADR-0025`–`ADR-0027`):**
  - Keep deterministic PDF cleaning (`PDFTextCleaner`, `protect_normative_lines=True`), IEEE-830 heading promotion, `SectionRole` triage (`GLOSSARY_ONLY`/`BACKGROUND_REFERENCE` = `0` LLM calls), and TF-IDF cosine-valley chunking (`<= 3,400` chars) enabled by default ahead of LLM decomposition, paired with `cluster_requirements_into_batches()` in critics and trace-preserving `deduplicate_requirements()`.
- **Windows PowerShell 5.1 & Live-Gate Shell Discipline:**
  - PowerShell 5.1 does not support `&&` (use `; if ($LASTEXITCODE -eq 0) { ... }`) and does not glob-expand `tests/test_*.py` for pytest (pass explicit test files or `tests/reqhq`).
  - Always prepend Temurin Java 21 (`C:\Program Files\Eclipse Adoptium\*\bin`) to `PATH` alongside `REQHQ_ALLOY_JAR_PATH` when running live Alloy gates so `@pytest.mark.alloy_live` executes with **0 skipped**.
  - Whenever runtime defaults, provider wiring, or evaluation architecture change, record the decision via `ADRManager` (`docs/adr/`) and add a monotonic governance parity assertion in `tests/reqhq/test_adr_phase5.py`.
